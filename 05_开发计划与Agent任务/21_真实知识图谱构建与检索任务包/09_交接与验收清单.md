- [ ] 已读取 `03_技术方案与架构/07F_真实知识图谱构建与检索详细设计.md`。

- [ ] 已确认输入文档路径。

- [ ] 已检查当前 `git status --short`，不得覆盖他人改动。

## 3. 角色交接重点

| 交出角色 | 接手角色 | 必须交接 |
| --- | --- | --- |
| 数据库 Agent | 接口/后端 Agent | 表名、字段、索引、seed、vector 维度、nullable 字段 |
| 接口 Agent | 后端/前端/测试 Agent | API 字段、错误码、权限、Mock 场景、状态枚举 |
| Python AI Agent | 后端/测试 Agent | parse/extract/retrieve-plan 请求响应、支持的 sourceType、降级方式 |
| 后端 Agent | 前端/测试 Agent | API 可用状态、真实/Mock 边界、Neo4j 初始化方式、发布/回滚限制 |
| 前端 Agent | 测试 Agent | 页面路径、按钮状态、空/加载/错误态、测试路径 |
| 测试 Agent | 主控 Agent | 缺陷清单、验证报告、阻塞项、是否可进入下一阶段 |

## 4. 最终验收清单

### 4.1 数据链路

- [ ] 创建知识源成功，返回 sourceId。
- [ ] parse action 后生成 knowledge_block。
- [ ] extract action 后生成 candidate entity/relation。
- [ ] 低置信度或冲突候选进入 review task。
- [ ] build action 后生成 draft graph revision。
- [ ] publish action 后 active revision 生效。
- [ ] rollback action 后 active revision 恢复到指定版本。

### 4.2 Neo4j 图谱

- [ ] 节点包含 tenantId、projectId、entityId、entityType、name、revisionId、status。
- [ ] 关系包含 relationId、relationType、sourceRefs、evidenceRefs、confidence、revisionId、status。
- [ ] draft/reviewing 不进入诊断检索。
- [ ] published active revision 可被路径查询命中。
- [ ] Cypher 全部参数化。

### 4.3 pgvector

- [ ] knowledge_block 有 embedding 字段。
- [ ] 向量查询按 tenantId/projectId 过滤。
- [ ] 向量召回结果只作为 evidence，不直接生成关系。

### 4.4 前端

- [ ] 分类、实体类型、关系类型来自 taxonomy API。
- [ ] 录入页展示任务时间线。
- [ ] 候选实体/关系可查看 confidence 和 evidence。
- [ ] 图谱维护页支持筛选、版本、证据抽屉。
- [ ] 发布/回滚入口受状态和权限控制。

### 4.5 诊断检索

- [ ] `/graphs/search/diagnosis` 返回 graphPaths。
- [ ] 返回 sourceEvidence 和 vectorEvidence。
- [ ] 返回 suggestedMcpCapabilities。
- [ ] 记录 graph_query_log。
- [ ] 无图谱命中时给出降级结果，不伪造关系。

### 4.6 安全权限

- [ ] 项目隔离生效。
- [ ] 原文证据按角色脱敏或限制。
- [ ] 发布、回滚、复核需要权限。
- [ ] LLM 输入前有脱敏策略或明确 TODO。

## 5. 不通过条件

出现以下任一情况，不允许标记完成：

1. 仍然只返回 Mock JSON 图谱。
2. 只做 chunk + embedding，没有实体和关系。
3. LLM 输出直接写入 published 图谱。
4. 没有 evidenceRefs 的关系进入 published。
5. draft 图谱被诊断检索使用。
6. 前端分类/关系类型写死。
7. 越权可以看到其他项目图谱。
8. 发布/回滚没有版本记录。
