# Intelligent Customer Service System 需求规格说明书

## 1. 文档信息

- 文档版本：V0.1
- 对应需求：面向 wnx-web 与 wnx-serve 的智能客服与诊断协同平台
- 编写人：Copilot 初始化
- 评审状态：初版待评审

## 2. 需求理解

- 目标用户与画像：以客服坐席、运维工程师、研发审批人、项目管理员为核心用户，使用场景集中在设备异常、告警异常、配置异常、日志核验与处理建议。
- 解决的核心问题：将研发个人经验中的问题定位路径、实时查询方法、风险动作判断标准沉淀成系统能力。
- 典型使用场景：设备离线排查、告警未触发排查、统计异常定位、协议字段映射核验、运维任务失败定位。
- 替代方案与现状：当前主要依赖客服找研发、研发手工查库查日志、口头或群消息协同，缺少结构化沉淀。
- 不做的影响：研发持续被高频答疑打断，现场问题恢复慢，知识无法复用，审批责任链不清晰。

## 3. 需求概述

- 需求背景：现有智慧工地/设备监管/告警平台问题类型复杂，涉及设备、协议、配置、告警、运维等多域协同。
- 需求目标（业务/管理/系统）：
	- 业务：提升客服与运维独立定位问题的比例。
	- 管理：建立证据链、审批链、审计链三条硬链路。
	- 系统：形成 Graph RAG + MCP + Agent + 审批执行的分层架构。
- 本期范围（核心功能）：问题接入、问题分类、实体抽取、知识检索、证据汇聚、诊断结论、执行日志、知识源录入、图谱查看维护、MCP 能力管理、诊断路径固化与反馈、工单/审批单生成、案例沉淀。
- 本期范围（边缘功能）：部分实时工具接入、低风险修复建议模板、与现有平台的菜单嵌入。
- 非本期范围 / 明确不做：直接替代原业务系统、全量自动执行高风险动作、全量覆盖所有设备协议与厂商。
- 监管 / 合规 / 安全 / 权限要求：严格按项目、角色、数据范围鉴权；高风险动作必须审批；所有查询与执行必须保留审计记录。

## 6. 业务流程

### 6.1 主流程

```text
客服坐席 / 运维工程师 在 [智能问答工作台] 提交问题
	-> 系统进行问题分类、实体抽取、上下文缺口识别
	-> 若上下文不足，系统发起补充追问并等待补齐
	-> 系统调用 Graph RAG 检索业务关系、历史案例、文档证据
	-> 系统按问题类型选择或生成诊断路径，编排 MCP 查询工具，获取实时状态、日志、配置、规则、任务信息
	-> 系统记录执行轨迹，包含命中的图谱、使用的路径、调用的 MCP、返回摘要、失败重试与降级原因
	-> 诊断 Agent 汇总证据，生成根因判断、置信度和建议动作
	-> 用户可查看执行日志，并反馈答案是否有效
	-> 用户可选择直接答复、生成工单或提交审批单
	-> 审批通过后才允许执行低风险或高风险动作
	-> 处理结果回写知识中心，成功路径可固化，失败路径进入重建或人工复核
```

### 6.2 异常流程

```text
若实体抽取不足
	-> 系统要求补充项目、设备、时间、问题现象
若 MCP 工具不可用
	-> 系统标记“实时证据缺失”，降级为静态知识答复并降低置信度
若审批未通过
	-> 系统保留诊断案例，终止执行任务，记录驳回原因
若执行失败
	-> 系统记录失败日志，必要时触发回滚建议与升级工单
```

### 6.3 边界流程

```text
若用户无项目权限
	-> 只返回脱敏提示，不展示项目数据
若问题跨多个设备或项目
	-> 系统拆分为多个诊断案例或提示用户缩小范围
若问题超出知识域
	-> 系统明确说明无法判断并建议转人工研发支持
```

## 11. 非功能需求

- 性能：普通问题 10 秒内返回第一屏诊断结论，复杂问题 30 秒内返回阶段性结果。
- 安全：禁止 LLM 直接连生产写接口，所有工具调用必须在受控工具层内完成。
- 权限：按项目、角色、数据范围三层控制，审批与执行权限独立。
- 审计：保留问题文本、工具调用、审批、执行、回滚与关闭结论全链路日志。
- 稳定性：工具层失败可降级，不影响会话继续。
- 可维护性：问题分类、工具编排、知识源接入应可扩展配置。
- 兼容性：支持桌面端工作台，后续可适配 wnx-web 菜单嵌入。
- 可观测性：Agent 推理链、工具调用结果、执行结果需要可观测与可追溯。
