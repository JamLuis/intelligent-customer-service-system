# 产品规划补充：问答、图谱、MCP 与诊断链路闭环

## 1. 背景判断

用户补充的“问答页面”不是单一聊天功能，而是对系统产品形态的关键修正：系统必须让用户看到 AI 如何分析、用了哪些知识图谱、调用了哪些 MCP、为什么得出这个答案，并允许管理员对知识、图谱、MCP 能力和诊断路径进行治理。

因此本项目的产品定位应从“智能问答 + 诊断建议”升级为“可解释、可治理、可复用路径的工程诊断平台”。

## 2. 产品目标补充

| 目标编号 | 产品目标 | 成功标准 | 优先级 |
| --- | --- | --- | --- |
| PM-G-001 | 诊断过程透明 | 每次问答都能展示图谱路径、MCP 调用、工具返回摘要、推理步骤和最终证据链 | P0 |
| PM-G-002 | 图谱可治理 | 用户可查看已生成图谱，管理员可二次编辑、维护、更新和回滚图谱关系 | P0 |
| PM-G-003 | 知识可录入 | 支持 doc、excel、pdf、jpg、png、纯文本等知识源录入，并进入解析、抽取、入图流程 | P0 |
| PM-G-004 | MCP 能力可管理 | 展示系统所有 MCP 能力，支持启用、停用、查看能力边界、查看调用审计 | P0 |
| PM-G-005 | 诊断路径可固化 | 对成功路径进行沉淀复用，降低同类问题在不同时间回答不稳定的随机性 | P0 |
| PM-G-006 | 失败路径可重建 | 当答案不符合现场或无法得到答案时，用户可触发路径重建和人工复核 | P1 |

## 3. 新增核心业务对象

| 对象编码 | 对象名 | 业务含义 | 关键字段 | 关联对象 |
| --- | --- | --- | --- | --- |
| O-006 | 执行轨迹 ExecutionTrace | 一次问答诊断的可解释过程记录 | traceId、caseId、graphPaths、mcpCalls、reasoningSteps、finalAnswer、confidence | 诊断案例、证据项、MCP 调用 |
| O-007 | 图谱资产 GraphAsset | 已生成或人工维护的图谱节点、关系、子图和版本 | graphId、graphType、nodes、edges、version、status、sourceRefs | 知识源、代码图谱、协议、工单 |
| O-008 | 知识源 KnowledgeSource | 用户录入的文件、图片、文本和批量资料 | sourceId、sourceType、fileName、parserStatus、extractStatus、graphBuildStatus、sensitivityLevel | 图谱资产、知识案例 |
| O-009 | MCP 能力 McpCapability | 系统可调用的 MCP 工具能力及边界 | capabilityId、name、category、riskLevel、enabled、inputSchema、outputSchema、boundary | 执行轨迹、诊断路径 |
| O-010 | 诊断路径 RouteTemplate | 已固化或待验证的问题分析路线 | routeId、questionPattern、graphStrategy、mcpPlan、successRate、status、version | 诊断案例、执行轨迹、MCP 能力 |
| O-011 | 路径评估 RouteEvaluation | 用户或系统对诊断路径有效性的反馈 | evaluationId、routeId、caseId、rating、failureReason、rebuildRequired | 诊断路径、执行轨迹 |

## 5. 关键产品流程

### 5.1 问答诊断透明化流程

```text
用户提交问题
  -> 系统识别问题类型和关键实体
  -> 系统查询可用诊断路径 RouteTemplate
  -> 若命中稳定路径，则按路径执行图谱检索和 MCP 调用
  -> 若未命中，则动态规划图谱路径与 MCP 调用链
  -> 系统记录 ExecutionTrace：图谱、MCP、推理、耗时、降级
  -> 输出答案、证据链和执行日志
  -> 用户反馈“有效 / 无效 / 部分有效”
  -> 成功路径更新成功率；失败路径进入重建或人工复核
```

### 5.2 知识录入到图谱流程

```text
管理员上传文件 / 图片 / 文本
  -> 系统创建 KnowledgeSource
  -> 解析文件结构和 OCR 内容
  -> 抽取实体、关系、字段、规则、流程
  -> 生成候选 GraphAsset
  -> 低置信度关系进入人工复核
  -> 审核通过后发布图谱版本
  -> 图谱可被问答页面和诊断路径引用
```

### 5.3 MCP 能力治理流程

```text
管理员登记 MCP 能力
  -> 填写能力简介、输入输出、风险等级、能力边界
  -> 设置启用状态与角色权限
  -> 诊断路径可引用该能力
  -> 每次调用写入 ExecutionTrace
  -> 能力异常或风险变化时可停用
```

### 5.4 诊断路径固化与重建流程

```text
动态诊断得到有效结果
  -> 用户或系统标记为成功路径
  -> 系统生成/更新 RouteTemplate
  -> 后续相似问题优先复用该路径
  -> 若用户反馈答案不符合现场
      -> 创建 RouteEvaluation
      -> 标记路径为待复核或停用
      -> 触发路径重建并生成新版本
```

## 6. 新增业务规则

| 编号 | 规则 | 说明 | 优先级 |
| --- | --- | --- | --- |
| BR-005 | 每次诊断必须生成 ExecutionTrace | 即使最终无答案，也必须记录使用了哪些图谱、MCP、失败原因和降级原因 | P0 |
| BR-006 | MCP 能力默认最小权限启用 | 新能力上线前必须声明能力边界、风险等级、输入输出和可见角色 | P0 |
| BR-007 | 图谱人工编辑必须版本化 | 每次人工编辑节点或关系都要保留版本、编辑人、理由和回滚入口 | P0 |
| BR-008 | 知识源入图必须可追溯 | 图谱节点和关系必须能追溯到文件、页码、段落、图片或文本来源 | P0 |
| BR-009 | 成功路径可固化，失败路径可重建 | 成功路径累计提升稳定性；失败或不符合情况的路径不得继续无提示复用 | P0 |
| BR-010 | 路径固化不能绕过权限 | 即使路径被固化，执行时仍需按用户权限、MCP 状态、风险等级实时校验 | P0 |

## 7. 主要缺口与待确认

| 编号 | 缺口 | 影响 | 建议处理 |
| --- | --- | --- | --- |
| PM-GAP-001 | 图谱人工编辑的审核机制未明确 | 影响错误关系写入生产图谱的风险控制 | P0 先要求管理员编辑，P1 增加双人审核或发布审批 |
| PM-GAP-002 | 知识源支持图片 OCR 的准确率与人工复核边界未明确 | 影响图片、扫描件入图质量 | 将低置信度 OCR/抽取结果进入复核任务 |
| PM-GAP-003 | 诊断路径成功/失败的判定标准未明确 | 影响路径固化和重建策略 | 定义用户反馈、重复命中率、人工确认三类指标 |
| PM-GAP-004 | MCP 能力停用后的路径降级策略未明确 | 影响已固化路径稳定性 | 路径执行前实时校验能力状态，停用则重新规划 |
| PM-GAP-005 | 执行日志展示的敏感字段范围未明确 | 影响客服、运维、审计角色可见内容 | 按角色拆分摘要日志、详细日志、原始返回 |

## 8. 版本规划建议

| 版本 | 范围 | 必须完成 | 可后置 |
| --- | --- | --- | --- |
| V0.1 | 可解释问答闭环 | 问答页面、执行日志、基础知识录入、MCP 能力列表、ExecutionTrace | 图谱人工编辑高级审核 |
| V0.2 | 图谱与路径治理 | 知识图谱页面、图谱版本、MCP 启停、路径固化、路径反馈 | 路径自动评分 |
| V0.3 | 复核与半自动优化 | 路径重建、复核任务、失败路径治理、成功路径更新 | 复杂审批策略 |

## 9. 产品结论

本项目 P0 不应只追求“能回答”，而应优先做到“回答可解释、路径可追溯、能力可治理、知识可入图”。否则系统会变成不可控的聊天框，难以在真实工程诊断场景中被客服、运维和研发信任。
