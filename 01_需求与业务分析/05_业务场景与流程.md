# Intelligent Customer Service System 业务场景与流程

## 1. 业务场景清单

| 编号 | 场景名称 | 触发角色 | 前置条件 | 结果 | 优先级 |
| --- | --- | --- | --- | --- | --- |

| SC-002 | 告警未触发问题定位 | R-CS / R-OPS | 已知设备、告警类型、时间范围 | 输出规则、阈值、映射、任务状态与结论 | 高 |
| SC-003 | 数据统计异常定位 | R-OPS | 已知项目与统计指标 | 输出任务状态、源数据情况与修复建议 | 中 |
| SC-004 | 高风险修复动作审批 | R-OPS / R-RD | 已有诊断结论与风险分级 | 形成审批单并决定是否执行 | 高 |

## 2. 主流程

### 2.1 设备离线问题定位

- 触发条件：用户反馈设备离线、没有数据、现场看起来正常。
- 参与角色：R-CS、R-OPS
- 步骤：
1. 用户在工作台输入问题，并尽量附带项目、设备、时间。
2. 系统识别“设备问题”类别，抽取设备实体并检查是否缺失上下文。
3. Graph RAG 检索设备所属项目、协议、页面、相关历史案例。
4. MCP 查询设备在线状态、最后心跳、最近日志、同步任务状态。
5. 诊断 Agent 输出结论、证据链和建议动作。
- 结果状态：问题会话进入已分析，诊断案例进入已出结论。

### 2.2 告警未触发问题定位

- 触发条件：用户反馈明明超阈值但没有告警。
- 参与角色：R-CS、R-OPS
- 步骤：
1. 系统识别设备类型、告警类型、时间范围。
2. 图谱检索设备 -> 协议 -> 字段映射 -> 阈值配置 -> 告警规则 -> 页面展示链路。
3. MCP 查询设备数据、规则启用状态、阈值配置、任务日志、告警历史。
4. Agent 判断是数据缺失、映射错误、规则关闭还是任务未执行。
5. 输出诊断结论，并支持生成工单或审批单。
- 结果状态：诊断案例进入已出结论，必要时创建审批单。

### 2.3 高风险修复动作审批

- 触发条件：诊断结论建议执行重绑设备、恢复数据、重置告警规则等动作。
- 参与角色：R-OPS、R-RD、R-ADMIN、R-AUDIT
- 步骤：
1. 运维发起审批申请，系统写入动作说明、风险级别、证据链摘要。
2. 审批人查看上下文、证据、风险与影响范围。
3. 审批通过后，系统校验执行白名单并创建执行任务。
4. 执行完成后回填结果、日志与审计记录。
5. 若执行失败，转人工处理并记录原因。
- 结果状态：审批单进入已通过/已拒绝，执行任务进入成功/失败/回滚。

### 2.4 问答执行日志查看

- 触发条件：用户需要确认系统为什么给出当前答案。
- 参与角色：R-CS、R-OPS、R-RD、R-ADMIN、R-AUDIT
- 步骤：
1. 用户从问答页面或诊断结果页进入执行日志。
2. 系统展示本次诊断命中的图谱节点、关系路径、诊断路线、MCP 调用列表和返回摘要。
3. 系统按角色隐藏或展示原始日志、原始 MCP 返回和敏感字段。
4. 用户可基于执行日志判断答案是否有效，并提交有效、无效或部分有效反馈。
5. 系统根据反馈更新路径评估，必要时触发路径重建。
- 结果状态：执行轨迹进入已完成或部分完成；路径评估被创建或更新。

### 2.5 知识源录入与入图

- 触发条件：需要导入需求文档、设计文档、协议、配置表、运维记录、图片或故障材料。
- 参与角色：R-OPS、R-ADMIN
- 步骤：
1. 用户上传 doc、excel、pdf、jpg、png 或录入纯文本。
2. 系统创建知识源记录并进行文件解析、OCR、结构化恢复。
3. 系统抽取实体、字段、关系、规则、流程和异常场景。
4. 系统生成候选图谱，并标记低置信度和冲突关系。
5. 管理员复核后发布图谱版本。
- 结果状态：知识源进入已入图，图谱资产进入已发布。

### 2.6 图谱人工维护

- 触发条件：用户发现节点、关系、来源或版本不准确。
- 参与角色：R-OPS、R-ADMIN、R-AUDIT
- 步骤：
1. 运维在知识图谱页面检索节点或关系。
2. 运维提交编辑建议，填写修改原因和来源依据。
3. 管理员复核编辑内容，发布新版本或驳回。
4. 系统保留旧版本、差异记录和回滚入口。
5. 新版本生效后，问答诊断优先引用新图谱。
- 结果状态：图谱资产进入已发布、已废弃或已回滚。

### 2.7 MCP 能力管理与路径影响

- 触发条件：新增能力、能力异常、能力停用或风险等级变化。
- 参与角色：R-ADMIN、R-AUDIT
- 步骤：
1. 管理员查看 MCP 能力列表、输入输出、风险等级、调用边界和健康状态。
2. 管理员启用或停用能力，并填写原因。
3. 系统在路径执行前校验能力状态。
4. 如果固化路径引用停用能力，系统自动重规划或进入复核。
5. 审计人员查看能力变更和调用记录。
- 结果状态：MCP 能力进入已启用、已停用、异常或已退役。

### 2.8 调用链固化、重建与成功链路更新

- 触发条件：诊断答案被用户确认有效，或被反馈为无效/不符合现场。
- 参与角色：R-CS、R-OPS、R-RD、R-ADMIN
- 步骤：
1. 系统根据执行轨迹生成候选诊断路径。
2. 用户标记答案有效后，运维或管理员可固化路径。
3. 后续相似问题优先复用已固化路径，减少同类问题随机性。
4. 如果用户反馈无效，系统创建路径评估并进入复核。
5. 复核通过后生成新路径版本，旧路径停用或归档。
- 结果状态：诊断路径进入候选、已启用、复核中、已停用或已归档。

## 3. 异常流程

| 场景 | 异常条件 | 系统处理 | 用户反馈 | 后续状态 |
| --- | --- | --- | --- | --- |
| 设备离线定位 | 未识别设备 | 发起追问，要求补充设备或项目 | 请补充设备编号或所属项目 | 问题会话待补充上下文 |
| 告警未触发定位 | 实时工具失败 | 降级为静态知识结论 | 实时数据暂不可用，以下为经验诊断 | 诊断案例低置信度结论 |
| 高风险修复审批 | 审批拒绝 | 终止执行并记录驳回原因 | 审批未通过，请查看审批意见 | 审批单已拒绝 |
| 知识沉淀 | 敏感信息未脱敏 | 阻止发布 | 存在敏感信息，请先脱敏 | 知识案例草稿 |
| 执行日志 | 部分 MCP 调用失败 | 标记降级并保留失败原因 | 部分实时能力不可用，已降级分析 | 执行轨迹部分完成 |
| 知识入图 | OCR 或解析失败 | 标记失败并允许重跑 | 资料解析失败，请重试或转人工处理 | 知识源处理失败 |
| 图谱维护 | 同一关系存在多源冲突 | 转入人工复核 | 图谱关系存在冲突，请复核后发布 | 图谱资产复核中 |
| MCP 管理 | 能力被停用 | 阻止路径调用并重规划 | 相关能力已停用，系统将重新规划路径 | 诊断路径复核中 |
| 路径治理 | 答案不符合现场 | 创建路径评估并触发重建 | 已记录反馈，将进入路径复核 | 诊断路径复核中 |

## 5. 业务规则

1. 只要涉及执行动作，必须明确风险等级和审批要求。
2. 只要涉及结论输出，必须附带证据链和来源时间。
3. 只要涉及知识沉淀，必须处理敏感信息并保留原案例引用。
4. 每次问答诊断必须生成执行轨迹，记录图谱路径、MCP 调用、推理步骤、失败原因和降级原因。
5. 图谱人工编辑必须版本化，且发布、回滚、废弃都要留痕。
6. MCP 能力启停必须影响后续路径编排，已停用能力不得被新诊断调用。
7. 成功调用链允许固化复用；无答案、答案不符合现场或连续失败的路径必须进入重建或人工复核。
