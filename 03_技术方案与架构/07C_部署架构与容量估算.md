## 3. 部署拓扑（文字版）

```text
[公网 / 办公网]
  |-- WAF / LB
        |-- Nginx 2 节点
              |-- Spring Cloud Gateway 2 节点
                    |-- Diagnosis Orchestrator 2 节点
                    |-- Workflow Service 2 节点（Phase 2 启用）
                    |-- MCP Tool Server 2 节点
                          |-- wnx-web
                          |-- wnx-serve

[图谱构建与知识处理层]
      |-- Graph Ingestion Worker 2 节点
                        |-- Document Graph Pipeline（Docling / Unstructured / LlamaParse）
                        |-- Code Graph Pipeline（CodeGraph / TreeSitter）
                        |-- Protocol / API / DB / Case / Ops Extract
                        |-- Entity Normalize / Conflict Detect / Cross Link Agent / Merge Agent

[内网数据层]
  |-- PostgreSQL 主 1 + 只读副本 1
  |-- Redis 3 节点（哨兵）
  |-- Neo4j 1 节点（Phase 1）/ 3 节点集群（Phase 3 触发）
  |-- 对象存储（MinIO / S3）
  |-- Prometheus + Loki + Grafana
```

## 7. 安全边界

| 项 | 内容 |
| --- | --- |
| 网络分区 | 办公网 / DMZ / 内网数据层三层隔离 |
| 入口防护 | WAF、网关限流、IP 白名单、接口级黑名单 |
| 传输加密 | TLS 1.2+，内外部流量均走 HTTPS |
| 静态加密 | PostgreSQL 磁盘加密、对象存储服务端加密、备份文件加密 |
| 越权防护 | 网关统一鉴权 + 服务端项目级 RBAC + 字段脱敏 |
| 审计日志 | 工具调用、审批、执行、导出、登录与权限异常统一审计 |
| 密钥管理 | KMS 或集中配置中心，禁止明文落盘到仓库 |
| 合规 | 审批与审计链按内部合规要求执行，具体留存年限待确认 |

## 8. 高可用与故障域

| 故障域 | 影响范围 | 检测方式 | 自动处理 | 人工预案 |
| --- | --- | --- | --- | --- |
| 单节点宕机 | 对应无状态服务实例 | K8s / 进程守护 + 健康检查 | 自动摘流与拉起 | 检查 JVM / Node 日志并补采样 |
| 单可用区故障 | 整个应用层或数据层 | 节点存活监控、LB 健康检查 | 无，需人工切换灾备或停写策略 | 按 RTO/RPO 执行恢复 |
| 数据库主库故障 | 会话、案例、审计写入受阻 | 主从复制延迟、存活检查 | 只读切换不自动写切换 | 人工主从切换并验证一致性 |
| Redis 故障 | 缓存、限流、SSE 状态受影响 | Redis exporter | 哨兵切主 | 临时降级为无缓存模式 |
| Neo4j 故障 | Graph 检索失效 | Neo4j 监控 + 业务探针 | 无 | 降级为 RAG + MCP |
| 文档解析 Worker 故障 | 新文档无法入图，存量诊断可继续 | 队列积压、任务心跳、失败率告警 | 任务重试与实例重启 | 暂停新增 sourceVersion，人工补跑 |
| Cross Link Agent 误关联 | 诊断路径可能出现错误工程关系 | 低置信度比例、人工驳回率、抽样审计 | 高风险关系不自动入主图 | 回滚构建批次并修正规则 |
| 第三方依赖故障 | 上游接口、LLM、审批不可用 | 接口探针、错误率告警 | 熔断、降级、切备用模型 | 转人工工单与暂停执行 |
| 全站故障 | 所有功能不可用 | 黑盒探针、告警总线 | 无 | 按灾备流程恢复 |

## 9. 灾备 / 备份 / 回滚

| 项 | 内容 |
| --- | --- |
| RTO | 2 小时【假设】 |
| RPO | 15 分钟【假设】 |
| 备份策略 | PostgreSQL 每日全量 + 15 分钟 WAL 归档；Neo4j 每日备份；对象存储按桶版本策略 |
| 演练频率 | 每季度一次恢复演练 |
| 回滚策略 | 应用按版本回滚；数据库仅做前向兼容迁移；配置变更独立版本化 |
| 灰度策略 | 先 staging，全量回归后按用户组或项目灰度 10% -> 50% -> 100% |

## 10. 可观测性

| 维度 | 工具 | 关键指标 | 告警阈值 | 接收人 |
| --- | --- | --- | --- | --- |
| 日志 | Loki | 工具失败日志、审批失败日志、异常堆栈 | 5 分钟内错误数 > 50 | 研发 / 运维 |
| 指标 | Prometheus | QPS、P95 时延、SSE 并发、缓存命中率 | P95 超阈值 10 分钟 | 研发 / 运维 |
| 链路 | OpenTelemetry | 诊断全链路耗时、工具扇出耗时 | 单链路 > 20 秒 | 研发 |
| 业务监控 | Grafana | 诊断成功率、低置信度比例、审批滞留数、执行失败率 | 成功率 < 95% / 滞留 > 20 | 产品 / 运维 / 研发 |
