# Intelligent Customer Service System 数据流与集成方案

## 1. 文档信息

- 对应需求：智能诊断与客服平台
- 编写人：Copilot 初始化
- 版本：V0.1

## 2. 数据流总览

```text
[多源工程知识构建流]
代码仓库 / 文档 / 协议 / OpenAPI / DB Schema / 工单 / 日志
	-> Source Registry 登记来源、版本、权限
	-> Document / Code / Protocol / API / DB / Case / Ops Extract
	-> Entity Normalize
	-> Conflict Detect
	-> Cross Link Agent
	-> Merge Agent
	-> Neo4j Unified Engineering Graph
	-> PostgreSQL + pgvector 保存 source、chunk、embedding、构建批次

[用户提问]
	-> [Frontend]
	-> [Gateway]
	-> [Diagnosis Orchestrator]
	-> [问题会话 / 诊断案例写入 PostgreSQL]
	-> [Planner 同时触发 Graph / RAG / MCP 查询]
			 -> Graph: 业务关系检索（Neo4j）
			 -> RAG: 文档 / 历史案例检索（PostgreSQL + pgvector）
			 -> MCP: 实时状态 / 日志 / 配置 / 规则查询（Node MCP -> 上游系统）
	-> [Evidence Builder 汇聚证据]
	-> [LLM 整合输出结论]
	-> [前端展示结论与证据链]
	-> [如需执行 -> Workflow 审批]
	-> [审批通过 -> MCP 执行动作]
	-> [结果与审计回写 PostgreSQL]
	-> [关闭案例 -> 知识切片与 Graph 关系增量更新]
```

## 2.1 多源工程图谱入图主链路

| 数据源 | 解析方式 | 抽取实体 | 抽取关系 | 入库目标 |
| --- | --- | --- | --- | --- |
| 需求 / 设计 / 运维 / 部署文档 | Docling / Unstructured / LlamaParse + LLM Extract | 设备、模块、角色、规则、页面、字段、配置、告警、流程 | TRIGGERS、DEPENDS_ON、DISPLAYS、BELONGS_TO、CONTROLS | Neo4j、PostgreSQL source/chunk、pgvector |
| 研发代码仓库 | CodeGraph + TreeSitter + AST | Repository、File、Class、Method、Controller、Service、Mapper、DTO、Page | CALLS、IMPORTS、QUERIES、DISPLAYS | Neo4j、PostgreSQL build batch |
| 设备协议 | Protocol Agent + LLM Extract | Protocol、Metric、Field、Unit、Threshold、AlarmTrigger | HAS_FIELD、TRIGGERS、MAPS_TO | Neo4j、PostgreSQL source/chunk |
| OpenAPI / 接口说明 | API Extract | API、Endpoint、Parameter、DTO、ErrorCode | HAS_PARAM、RETURNS、CALLS、MAPS_TO | Neo4j、PostgreSQL metadata |
| 数据库 | information_schema / DDL Extract | Schema、Table、Column、Index、Enum、Dictionary | HAS_COLUMN、INDEXES、REFERENCES、MAPS_TO | Neo4j、PostgreSQL metadata |
| 工单 / 研发记录 | Case Extract | Incident、Symptom、Cause、FixAction、Owner、Evidence | POSSIBLE_CAUSE、FIXED_BY、VERIFIED_BY | Neo4j、PostgreSQL case metadata |
| 运维日志 / 指标 | Ops Extract / MCP log tools | Metric、Alert、LogPattern、TraceId、Job、ConsumerGroup | OBSERVED_IN、TRIGGERS、AFFECTS | Neo4j、Loki/Prometheus 引用、PostgreSQL audit |

## 2.2 Cross Link Agent 数据流

```text
候选实体
	-> Embedding 召回相似名称和上下文
	-> 规则匹配别名、枚举、单位、模块、项目范围
	-> LLM 验证同义、上下位、依赖、因果、配置映射
	-> Conflict Detect 标记同名异义、版本冲突、单位冲突
	-> 高置信度关系写入 Neo4j
	-> 低置信度或高风险关系进入人工复核任务
```

示例统一链：`超载告警 -> OVERLOAD_ALARM -> alarm_type=101 -> alarm_rule -> moment 字段 -> 塔吊协议 -> 实时告警状态`。

## 3. 数据流明细（每条流一节）

### 3.1 [DF-001] 问题接入与诊断会话流

| 项 | 内容 |
| --- | --- |
| 业务场景 | 客服或运维提交问题并发起诊断 |
| 数据来源 | 用户手工输入的问题文本、项目、设备、时间范围 |
| 接入协议 | HTTP + SSE |
| 频率/吞吐量（量化） | 【假设】日均 2000 次诊断，峰值 5 req/s，SSE 并发 30 |
| 数据量（量化） | 单次问题输入 1 到 2KB，单次诊断结果 10 到 50KB |
| 写路径 | Frontend -> Gateway -> Diagnosis Orchestrator -> PostgreSQL |
| 一致性策略 | 强一致 |
| 事务边界 | 问题会话、诊断案例主记录与审计记录在同一事务内提交 |
| 读路径 | PostgreSQL 主库 + Redis 热点缓存 + SSE 状态流 |
| 缓存策略 | 会话与诊断状态缓存 TTL 5 分钟；重复读取结果缓存 TTL 30 秒 |
| 失败处理 | 前端最多重试 1 次；服务端以 requestId 防重复；失败后保留草稿 |
| 幂等键 | requestId / sessionId |
| 顺序性要求 | 按 sessionId 有序 |
| 保留期 | 【假设】热数据 90 天，冷数据 24 个月 |
| 可观测 | 会话创建耗时、诊断启动耗时、SSE 中断率、诊断首屏返回时延 |

### 3.2 [DF-002] 图谱构建与增量更新流

| 项 | 内容 |
| --- | --- |
| 业务场景 | 将代码、文档、协议、接口、数据库、工单、日志沉淀成统一工程知识图谱 |
| 数据来源 | 研发代码仓库、需求/设计/部署/运维文档、协议文档、OpenAPI、information_schema、工单、日志平台、知识案例 |
| 接入协议 | HTTP / 文件导入 / 批处理任务 |
| 频率/吞吐量（量化） | 【假设】每日 1 到 4 次增量构建，每次新增 500 到 5000 个节点/关系 |
| 数据量（量化） | 每日增量 5 到 20MB |
| 写路径 | Source Registry -> Extract Pipeline -> Entity Normalize -> Conflict Detect -> Cross Link Agent -> Merge Agent -> Neo4j |
| 一致性策略 | 最终一致 |
| 事务边界 | 单批次节点与关系导入为单事务或分批事务 |
| 读路径 | Diagnosis Orchestrator -> Neo4j |
| 缓存策略 | 热门 graphPath 结果缓存 TTL 5 分钟 |
| 失败处理 | 导入失败进入重试队列；三次失败转人工补录 |
| 幂等键 | sourceId + sourceVersion + extractorVersion |
| 顺序性要求 | 按 sourceType 局部有序 |
| 保留期 | 图谱长期保留，历史版本保留策略待业务确认 |
| 可观测 | 图谱导入成功率、节点关系增量、跨源关联成功率、冲突率、人工复核积压、查询耗时、坏链比例 |

### 3.3 [DF-003] RAG 知识入库与检索流

| 项 | 内容 |
| --- | --- |
| 业务场景 | 将手册、运维记录、案例、配置说明切片并建立向量索引 |
| 数据来源 | 手册、协议说明、工单、诊断案例、数据库说明 |
| 接入协议 | 文件导入 / HTTP 批量提交 |
| 频率/吞吐量（量化） | 【假设】每日新增 2000 到 10000 个 chunk，检索峰值 20 次/秒 |
| 数据量（量化） | 单 chunk 0.5 到 2KB，日增 10 到 30MB |
| 写路径 | Ingestion Task -> Embedding Provider -> PostgreSQL + pgvector |
| 一致性策略 | 最终一致 |
| 事务边界 | chunk 元数据与向量写入单事务 |
| 读路径 | Diagnosis Orchestrator -> similarity search -> metadata query |
| 缓存策略 | 常见问题检索结果缓存 TTL 10 分钟 |
| 失败处理 | embedding 失败重试 2 次，仍失败则进入人工重处理清单 |
| 幂等键 | chunkHash |
| 顺序性要求 | 否 |
| 保留期 | 【假设】知识 chunk 24 个月，过期后归档冷存储 |
| 可观测 | embedding 成功率、检索耗时、召回数、失效率 |

### 3.4 [DF-004] MCP 实时查询证据流

| 项 | 内容 |
| --- | --- |
| 业务场景 | 诊断时查询设备状态、规则、日志、任务状态、项目配置 |
| 数据来源 | wnx-web、wnx-serve、日志平台 |
| 接入协议 | Orchestrator -> MCP 内部调用；MCP -> 上游 HTTP / SDK |
| 频率/吞吐量（量化） | 单次诊断平均 3 到 8 个工具调用；【假设】峰值 40 次工具调用/秒 |
| 数据量（量化） | 单次工具返回 1 到 20KB，日志检索可到 100KB |
| 写路径 | Diagnosis Orchestrator -> MCP -> 上游系统，查询结果仅回写 PostgreSQL 审计和短期缓存 |
| 一致性策略 | 查询型操作为最终一致，取决于上游系统实时性 |
| 事务边界 | 单工具调用无分布式事务，结果回写审计单独提交 |
| 读路径 | 上游系统 -> MCP -> Orchestrator -> 前端 |
| 缓存策略 | 设备状态、规则、配置缓存 TTL 30 秒；日志检索默认不缓存 |
| 失败处理 | 只读查询超时 3 秒，最多重试 1 次；失败后降级静态知识 |
| 幂等键 | diagnosisId + toolName + parameterHash |
| 顺序性要求 | 按 diagnosisId 编排顺序执行，日志/统计类允许并行 |
| 保留期 | 审计摘要【假设】保留 24 个月，原始明细保留期依赖上游系统 |
| 可观测 | 工具耗时、错误率、熔断次数、上游依赖成功率、降级次数 |

### 3.5 [DF-005] 审批与执行闭环流

| 项 | 内容 |
| --- | --- |
| 业务场景 | 高风险或受控低风险动作进入审批、执行、回写 |
| 数据来源 | 诊断结论、审批意见、执行回调 |
| 接入协议 | HTTP + Workflow Callback |
| 频率/吞吐量（量化） | 【假设】一期小于 20 单/日，二期小于 100 单/日 |
| 数据量（量化） | 单审批单 2 到 10KB，执行日志单次 5 到 20KB |
| 写路径 | Orchestrator -> Workflow -> PostgreSQL -> 审批通过后 -> MCP 执行 -> 审计回写 |
| 一致性策略 | 跨系统最终一致 |
| 事务边界 | 审批单创建本地事务；执行采用 Saga 风格状态推进 |
| 读路径 | Workflow / PostgreSQL -> Frontend |
| 缓存策略 | 审批列表缓存 TTL 10 秒 |
| 失败处理 | 审批回调重试 3 次；执行失败不自动二次执行，转人工处理 |
| 幂等键 | approvalId / actionId |
| 顺序性要求 | 按 approvalId 有序 |
| 保留期 | 审批与执行审计【假设】保留 36 个月 |
| 可观测 | 审批耗时、执行成功率、回滚率、超时审批数 |

## 8. 数据一致性总表

| 数据流 | 写一致性 | 读一致性 | 跨服务一致性方案 | 风险 |
| --- | --- | --- | --- | --- |
| 问题接入与诊断会话 | 强 | 主库 + 缓存 | 本地事务 + 幂等请求 | 重复提交 |
| 图谱构建与增量更新 | 最终 | Neo4j 实时读 | 批处理重试 + sourceId 幂等 | 图谱延迟更新 |
| RAG 知识入库与检索 | 最终 | 主库 + 索引 | outbox + embedding 重试 | embedding 积压 |
| MCP 实时查询证据 | 最终 | 上游实时读 | 无分布式事务，审计异步回写 | 上游实时性受限 |
| 审批与执行闭环 | 最终 | 主库读 | Saga 风格状态推进 | 审批通过但执行失败 |
