# Intelligent Customer Service System 固定格式需求输入

## 1. 基本信息

- 项目名称：Intelligent Customer Service System
- 需求名称：面向 wnx-web 与 wnx-serve 的智能客服与诊断协同平台
- 提出部门：研发与平台运维协同
- 提出人：用户侧发起
- 日期：2026-05-22
- 优先级：高
- 计划版本：V0.1 初始化版

## 2. 业务背景

- 当前业务现状：设备监管、告警排障、配置核验、接口联调等问题高度依赖研发人工答疑，研发被频繁打断。
- 当前存在的问题：问题入口分散、排查链路依赖个人经验、缺少证据链闭环、低风险修复缺乏审批化标准流程。
- 不做的影响：研发支持成本持续升高，客服与运维无法独立定位问题，历史经验无法沉淀复用。
- 期望收益：减少 40% 至 60% 的研发答疑压力，让客服与运维可独立处理更大比例的常见问题。

## 3. 项目目标

- 业务目标：实现“问题理解 -> 证据查询 -> 诊断结论 -> 工单/审批 -> 知识沉淀”的标准闭环。
- 管理目标：对高风险执行动作建立分级审批与审计追踪，避免 LLM 直接操作生产系统。
- 系统目标：围绕 Graph RAG、MCP 查询层、诊断 Agent 与审批执行层构建可扩展平台。
- 验收成功标准：一期可完成问题分类、实体抽取、知识检索、证据链答复；二期可接入 wnx-web 与 wnx-serve 的实时查询；三期可对低风险动作执行审批后处理。

## 4. 目标用户与角色

| 角色 | 身份说明 | 当前职责 | 本次涉及动作 |
| --- | --- | --- | --- |
| 客服坐席 | 面向项目一线的业务答疑人员 | 受理用户问题、跟进工单 | 提问、查看诊断、创建工单、回填结果 |
| 运维工程师 | 平台运维与实施支持人员 | 排查设备、日志、任务问题 | 发起诊断、查看证据、申请执行低风险修复 |
| 研发审批人 | 模块负责人或平台主管 | 审批高风险修复动作 | 审批、驳回、补充执行要求 |
| 项目管理员 | 项目级配置与权限维护人员 | 配置知识源、权限、工具白名单 | 配置数据源、权限、阈值、执行策略 |
| 审计人员 | 关注合规与执行记录 | 审计操作链路 | 查看审批与执行审计日志 |

## 5. 本期范围

- 本期必须实现：问题受理、问题分类、实体抽取、补充追问、Graph RAG 检索、证据链展示、诊断建议输出、系统执行日志、知识库录入、MCP 能力管理、图谱查看基础能力、调用链固化与反馈、工单生成、审批单生成、知识沉淀入口。
- 本期可选实现：接入部分实时查询工具、低风险修复建议模板、试点项目知识图谱增量同步、图谱人工编辑审核、路径自动评分。
- 明确不做：直接自动执行 L4/L5 动作、替代原有 wnx-web 或 wnx-serve 核心业务页面、全量设备协议自动建模。

## 6. 业务流程概述

- 主流程：用户提交问题 -> Agent 分类并抽取实体 -> 选择或生成诊断路径 -> Graph RAG 检索业务关系 -> MCP 工具查询实时数据 -> 记录执行轨迹 -> 输出带证据链的诊断结论 -> 用户反馈答案效果 -> 成功路径固化或失败路径重建 -> 生成答复、工单或审批单 -> 执行结果回写知识库。
- 异常流程：实体识别不足时发起追问；实时工具不可用时降级为静态知识答复并明确置信度下降；审批未通过时只保留建议不执行。
- 边界流程：无权限用户只能查看脱敏结论；缺少项目或设备上下文时禁止直接生成执行方案；高风险操作必须挂起等待人工审批。

## 7. 关键业务规则

1. 所有结论必须附带证据链，至少包含数据来源、时间、关键字段或日志摘要。
2. 执行动作按 L0-L5 分级，L3 可配置审批，L4/L5 必须人工审批并保留审计。
3. 每个已关闭案例都必须沉淀问题、原因、排查路径、处理方式和影响对象，反哺知识库。
4. 任何查询类工具都必须鉴权到项目、角色和数据范围，不允许跨项目越权检索。
5. 每次问答诊断必须保留执行轨迹，记录图谱命中、MCP 调用、推理步骤、失败原因和降级原因。
6. 成功调用链允许固化复用，失败或不符合现场的调用链必须进入重建或人工复核。
7. MCP 能力必须可启用、停用、审计，并在诊断路径执行前实时校验可用状态。

## 11. 非功能要求

- 性能要求：常规查询类问答在 10 秒内返回首个结论；复杂诊断在 30 秒内返回阶段性结果。
- 安全要求：LLM 不允许直接访问生产数据库写接口；所有执行动作必须经过白名单控制。
- 权限要求：按项目、角色、数据范围控制查询与审批可见性。
- 审计要求：保存问题输入、工具调用记录、审批记录、执行记录与最终结论。
- 可用性要求：外部工具失败时允许退化为静态知识答复，不得直接中断会话。
- 兼容性要求：支持桌面端工作台，后续可扩展嵌入现有前端系统。

## 12. 已知约束

- 技术约束：现有目标系统分别以 Vue 2 与 Spring Boot 体系存在，新系统需要低侵入接入。
- 业务约束：不同项目、设备厂家、协议与告警规则差异大，必须允许逐步建模。
- 时间约束：建议按三阶段推进，先做问答与定位，再接实时查询，最后做审批执行。
- 资源约束：一期不应要求大规模改造 wnx-web 与 wnx-serve。

## 13. 验收标准

| 编号 | 验收项 | 验收方式 | 验收标准 |
| --- | --- | --- | --- |
| AC-001 | 问题分类与实体抽取 | 场景测试 | 对设备、项目、时间、问题类型可输出结构化实体 |
| AC-002 | 证据链答复 | 集成演示 | 每次结论均展示至少 3 条可追溯证据 |
| AC-003 | 工单与审批生成 | 业务流程测试 | 可从诊断结论一键生成工单或审批单 |
| AC-004 | 动作分级控制 | 安全测试 | 未审批的 L4/L5 动作不可执行 |
| AC-005 | 知识沉淀 | 回归测试 | 关闭案例后可回写知识中心并被检索到 |
| AC-006 | 系统执行日志 | 场景测试 | 每次诊断均可查看图谱路径、MCP 调用和降级原因 |
| AC-007 | 知识库录入 | 流程测试 | 文件、图片或文本可创建知识源并进入解析/抽取/入图状态 |
| AC-008 | MCP 能力管理 | 权限测试 | 管理员可启停能力，停用后路径不得继续调用该能力 |
| AC-009 | 调用链固化与重建 | 回归测试 | 成功路径可复用，用户反馈无效后进入复核或重建 |

## 14. 已知风险

| 风险 | 说明 | 影响 | 备注 |
| --- | --- | --- | --- |
| 接口清单缺失 | 二期实时接入所需接口未固化 | 影响 MCP 工具设计 | 已登记到风险清单 |
| 审批流未确定 | 三期执行闭环依赖真实审批人和流程 | 影响执行模块设计 | 架构阶段需优先澄清 |
| 图谱质量不稳定 | 初期知识源质量决定检索效果 | 影响诊断可信度 | 需要分阶段建设 |
| 路径固化策略不清 | 调用链固化粒度和成功标准未定 | 影响同类问题稳定性 | 需补齐项目级/类型级/全局策略 |
| MCP 启停影响路径 | 能力停用可能影响已固化路径 | 影响诊断连续性 | 路径执行前必须校验能力状态 |
