# 智能诊断平台 UE 绘制规范

## 1. 设计方向

本平台采用混合风格：Palantir Gotham + Tesla FSD + Apple Vision Pro + Datadog + Cursor。

目标不是传统后台管理界面，而是“AI 正在执行诊断任务”的专业控制台体验。

核心感知关键词：

- 深色专业
- 实时诊断
- 证据可追溯
- 工单可闭环
- 管理可量化

## 2. 视觉规范

### 2.1 深色主题

- 主背景：#0B1220
- 次级背景：#101827
- 三级背景：#172033

建议：页面背景使用渐变叠层和轻噪点纹理，避免纯平面深色导致“死黑”。

### 2.2 Glassmorphism 半透明卡片

卡片样式基线：

- 半透明背景（深色 + 低透明）
- backdrop-filter: blur(20px)
- 细边框（低透明亮边）
- 柔和阴影与高光边缘

### 2.3 高亮语义色

- AI 主色：#3B82F6
- 成功状态：#10B981
- 告警状态：#F59E0B
- 危险状态：#EF4444

建议规则：

- 蓝色只用于“可执行智能动作”和“关键可点击信息”。
- 绿色只用于“已完成、稳定”。
- 橙色用于“需关注但未升级”。
- 红色用于“中断、超时、高风险”。

## 3. 产品信息架构

形成完整产品矩阵：

1. 案件中心（历史工单）
2. AI 诊断中心（核心页面）
3. 案例知识库（知识沉淀）
4. 运营分析驾驶舱（管理层）

对应链路：

案件进入 -> AI 诊断 -> 证据沉淀 -> 运营复盘

## 4. 核心页面布局（AI 诊断中心）

优先绘制 1920 x 1080 高保真页，布局比例：

- 左 20%：案件中心
- 中 50%：AI 会话中心
- 右 30%：证据链与结论工单区

风格参考：Cursor + Palantir。

## 5. 分区详细规范

### 5.1 左侧：案件中心（原“历史会话”）

命名要求：

- 不使用“聊天记录”。
- 推荐命名为“案件中心”或“会话工单”。

设计意图：每个会话本质是一个 Case，而不是聊天消息串。

案例列表示例：

- 长江2号地图不显示
- 驾驶舱抓图失败
- 告警推送异常
- 巡查漏检争议
- 设备离线分析

每个案件卡片至少展示：

- 标题
- 状态
- 时间
- 负责人
- 租户

案例条目示意：

- 标题：长江2号地图不显示
- 状态：处理中
- 时间：2026-06-01

### 5.2 中间：AI 会话中心

交互风格参考 Cursor，强调“执行过程可视化”，而不是仅输出最终答案。

用户输入示例：

- 为什么长江2号地图不显示

AI 输出结构建议：

- 正在分析...
- 步骤 1：检查船舶资料
- 步骤 2：检查定位上报
- 步骤 3：检查权限
- 步骤 4：检查地图筛选

关键设计原则：

- 必须展示诊断步骤进度，强化“AI 在工作”。
- 每个步骤应可关联右侧证据节点。
- 失败步骤要有明显状态色和重试动作。

### 5.3 右侧：诊断证据链（核心卖点区）

该区域不能折叠隐藏，必须长期可见。

示例链路：

- 船舶：长江2号
- 定位器：LOC-10001
- 最近定位：20 分钟前
- 状态：超时
- 结论：地图无法显示

故障树展示建议：

船舶
↓
定位器
↓
定位服务
↓
地图服务
↓
前端页面

设计目标：直观表达“知识图谱 + 证据推理”的价值。

### 5.4 底部：结论与工单区（最重要区域）

结论必须从聊天区抽离，单独成区，便于决策和交付。

固定模块：

- 根因分析
- 影响范围
- 处理建议
- 建议责任人
- 紧急程度

示例内容：

- 根因分析：船舶定位器 20 分钟未上传数据
- 影响范围：地图显示异常、实时轨迹异常、围栏判断异常
- 处理建议：检查定位器网络、检查 MQTT 连接、检查 AIS 服务
- 建议责任人：实施工程师
- 紧急程度：P2

工单动作：

- 增加“生成工单”按钮
- 点击后自动带入：工单标题、问题描述、根因、处理建议、附件、责任人

## 6. 第二页面：案例知识库

页面目标：复用历史经验，形成可持续学习能力。

核心能力：

- 搜索问题关键词（如：地图不显示）
- 返回历史案例列表
- 展示案例根因与处理动作

示例：

- 案例 1：定位器未绑定
- 案例 2：权限不足
- 案例 3：地图筛选导致不可见

业务价值：这是客户续费和扩容的关键理由，体现“系统越用越聪明”。

## 7. 第三页面：运营分析驾驶舱

页面目标：服务管理层，不以会话为中心，而以指标和趋势为中心。

建议核心指标：

- 本月处理案件：3241
- 平均定位时间：2.4 分钟
- AI 解决率：81%
- 高频问题 TOP10
- 高频设备故障 TOP10
- 高频告警 TOP10

展示原则：

- 以大数字卡 + 趋势图 + 排行榜为主。
- 所有核心指标支持下钻到案件与证据。

## 8. 首版绘制优先级

先完成 AI 诊断中心（1920 x 1080）高保真稿，并满足以下验收点：

1. 左 20% + 中 50% + 右 30% 比例落地。
2. 案件中心、AI 步骤诊断、证据链、结论工单四区完整。
3. 诊断步骤与证据链可以视觉联动。
4. 结论区支持一键生成工单。
5. 全局视觉风格符合深色 + Glassmorphism + 语义高亮规则。

后续再扩展案例知识库与运营分析驾驶舱页面。

## 9.1 推荐技术栈

目标：

- 仿真原型还原度 ≥ 90%
- 支持高保真交互演示
- 后续可直接转开发代码
- 支持 AI 诊断流程动态演示

推荐组合：

| 技术 | 用途 |
|--------|--------|
| React 18 + Vite + TypeScript | 主工程框架 |
| Ant Design | 表格、弹窗、表单、Tabs、分页、Tooltip |
| Tailwind CSS | 深色科技风、布局、间距、玻璃拟态样式 |
| Framer Motion | 动画系统、步骤流转、状态反馈 |
| ECharts | 统计图表、运营分析、趋势展示 |
| React Flow | 诊断证据链、知识图谱关系展示 |
| Zustand | 全局状态管理 |
| dayjs | 时间处理 |
| lucide-react / IconPark | 图标体系 |

## 9.2 为什么不使用纯 Ant Design

Ant Design 非常适合传统后台管理系统，但本项目目标并非传统管理后台，而是 AI 智能诊断平台。

需要重点体现：

- 深色玻璃拟态风格
- 发光边框效果
- AI 推理过程展示
- 证据链可视化
- 智能诊断步骤流
- 科技感导航与状态反馈

因此推荐采用：

```text
Ant Design
      +
Tailwind CSS
      +
自定义主题系统
```

即：

- Ant Design 负责基础组件能力
- Tailwind 负责视觉布局
- CSS Modules 负责高级视觉效果
